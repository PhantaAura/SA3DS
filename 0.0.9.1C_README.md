# SA3DS 0.0.9.1C — SET Decode + Object Placement Banks

**True cumulative source checkpoint:** based on the verified `0.0.9.1B` tree.
**Focus:** offline/owner-side Sonic Adventure DX SET structure import, not invented object behavior.

## Proven file structure

- All 71 recognizable `SETnnnnX.BIN` files from the owner's `system 2.zip` match the same shape: 32-byte header with little-endian u32 count at +0 and 28 zero bytes, followed by exactly `count` 32-byte entries.
- Records contain u16 type word, 3 signed16 rotation/angle words, 3 float32 position components, and 3 float32 **object-dependent parameters**.
- Both owner-supplied `system.zip` and `system 2.zip` contain the same 71 SET basenames with **71/71 matching SHA-256 hashes**.
- Source round-trip is byte-exact. No parameter or high-bit object-class semantics have been invented.
- All 71 checked files contain **30,085** records, grouped by filename into **45 numeric level/act groups** (no claim that all 45 are playable stages).
- Emerald Coast six source files total **3,664** placements across three acts: act 0 = 1,356; act 1 = 1,965; act 2 = 343.

## New code

- `tools/importers/pc2004_set.py`: format parser/strict validation, lossless source reconstruction, neutral `SA3DSET` chunk construction and verification, duplicate-name defense for directory/ZIP input, provenance hashes, and type-word histograms.
- `tools/build_pc2004_set_packages.py`: imports all recognized SET files (or a requested level) from a locally owned system directory/ZIP. Emits one owner-only `METADATA + SET` `.sa3dspak` per level/act numeric group and optional machine-readable manifest. These owner-derived packages are deliberately excluded from this source archive.
- `tools/build_pc2004_emerald_coast_visual.py --with-set`: optional addition of a `SET` chunk alongside existing geometry/material/texture chunks in the three existing Emerald Coast visual packages. Legacy invocation retains 1B output behavior.
- `tests/test_pc2004_set.py`: adversarial fixture and source-data tests, including exact 71-file inventory, corrupt header/CRC/provenance rejection, duplicate source rejection, owner-source round-trip, and complete 1C embedded stage integration.
- `tests/run_0_0_9_1C_tests.sh`: inherited 1B plus 1C regression entry point.

## Owner-only commands

```bash
# Source-side SET batch import. Generates owner-derived packages locally.
python3 tools/build_pc2004_set_packages.py \
  '/path/to/system 2.zip' /tmp/sa3ds_sets --report /tmp/sa3ds_sets.json

# Emerald Coast SET-only packages.
python3 tools/build_pc2004_set_packages.py \
  '/path/to/system 2.zip' /tmp/sa3ds_ec_sets --level-id 1

# Visual + materials + textures + SET placed into each owner-generated EC act package.
python3 tools/build_pc2004_emerald_coast_visual.py \
  '/path/to/sonic.exe' '/path/to/system 2.zip' /tmp/sa3ds_ec --with-set
```

## Boundaries / outstanding work

- All source records parsed, **but object classes and runtime behavior are NOT implemented**.
- Last three float32 values are kept as raw object-specific parameters; **not assumed to be geometric scale**.
- High bits of type word and suffix variant selection are unverified and preserved.
- Filename numeric level/act association is a grouping convention, not proof of event/script semantics.
- SET bank is pointer-free and signed/float semantics are preserved, but no Citro3D object-spawner integration in 1C.
- Old 3DS hardware test for 0G remains pending due to the user's charger.
- `PHYSICS_1TO1 = false` is unchanged.
