# SA3DS 0.0.9.0D — Real Sonic White-Space Render Gate

This checkpoint turns the validated PC2004 Sonic data pipeline into a real textured, animated white-space render path.

## What is proven here

- Exact PC2004 `CHRMODELS_orig.dll` profile remains the character-data source.
- Exact `SONIC.PVM` profile remains the Sonic texture source.
- Sonic hierarchy: 73 normal nodes.
- Base normal-pose geometry: 1,993 decoded triangles.
- 149 exported ACTION slots / 146 populated motions.
- 16 Sonic textures decode into a separate pointer-free `SA3T` staging package.
- Pointer-free `SA3C` geometry/animation package is consumed by native C readers.
- Native pose evaluation respects Ninja object flags and transform order.
- Host textured white-space raster smoke draws real Sonic geometry with real decoded texture pixels and a z-buffer.
- Real motion sampling changes the rendered pose.
- Source-supported Basic UV conversion uses `/255`.
- Basic quad triangulation now matches SA Tools: `0,1,2` and `2,1,3`.
- Sonic motion interpolation-function bits are clear (`NJD_MTYPE_LINER`), so all 146 populated Sonic motions use linear sampling for this source profile.
- The 2004 executable's dense 146-entry `SonicAnimData` table has been reconstructed and mapped back to the 149 exported ACTION slots; dense IDs 75 and 76 are intentionally null.

## Important boundary

This is a **source/import/runtime + host render gate**, not yet an Old 3DS Citro3D hardware-render checkpoint. No `.3dsx` is included here. The next gate should wire this same SA3C/SA3T data and pose/draw path into the user's devkitARM/Citro3D build and test it on real Old 3DS hardware.

## Distribution rule

No Sega-derived model, animation, texture, DLL, executable, PVM, generated SA3C, generated SA3T, or rendered source-asset image is included in this ZIP. Tools regenerate staging packages from the user's own supported install.
