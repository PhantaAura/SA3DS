# WIP5 — Full ACTION key integrity preflight

## Source-level gap

WIP4 sampled only frames 0, midpoint, and final. A malformed key at frame 1 can be skipped if the selected poses are at 0, 5, and 10 and the interpolator only touches keys surrounding those positions. This is a synthetic proof of a preflight coverage gap, **not** a claim that retail Sonic data is corrupted.

## Changes

- `src/game/sonic_action_preflight.c/.h`: scan every enabled position/rotation/scale track in each mapped ACTION in O(total keys) time. Check for empty enabled tracks, out-of-range spans, descending key timestamps, and nonfinite X/Y/Z values; retain WIP4 sampled local/world pose tests.
- `runtime_0_0_9_0F/source/main.c`: print actionable channel/track/key index on failure.
- `tools/check_sonic_actions.c`: portable read-only CLI for user-generated SA3C; validates file layout and references first, then all 17 exact source-backed binding slots.
- `tests/make_synthetic_sonic_sa3c.py`: generates entirely original synthetic fixtures, including a hidden NaN key.
- `tests/test_sonic_action_preflight.c`, `tests/run_sonic_action_preflight.sh`: adversarial track and CLI regressions.

Duplicate timestamps and keys at/outside the final clip frame are not rejected, because their exact PC2004 semantics remain unmeasured. Key ordering is required by the current interpolation algorithm. This is a safety gate, **not** verification of retail playback speed or action transitions.

## Run on owner's Mac

From the project source root, with a user-generated `sonic.sa3c` already produced by the existing owner-side importer:

```sh
cc -std=c11 -O2 -Wall -Wextra -Werror -Isrc/sa3c -Isrc/game \
  src/sa3c/sa3c_character.c src/sa3c/sa3c_pose.c \
  src/game/sonic_animation_runtime.c src/game/sonic_action_preflight.c \
  tools/check_sonic_actions.c -lm -o check_sonic_actions
./check_sonic_actions path/to/sonic.sa3c
```

Expected: `SA3C ACTION preflight PASS: 17 bindings, 51 sampled poses; all active track keys scanned`. Do **not** distribute the generated SA3C or any extracted Sega assets. A failure gives runtime ID, ACTION slot, frame, channel, track (1=pos, 2=rot, 4=scale), key index and pose error. This test does not require devkitARM and does not prove a 3DS build.
