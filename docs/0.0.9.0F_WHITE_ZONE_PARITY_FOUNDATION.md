# SA3DS 0.0.9.0F — Physics-Synced Real Sonic / White Zone Parity Foundation

## Purpose
This checkpoint begins the final controlled validation pass before Emerald Coast source decode. The White Zone is a developer-only original test course. It is intentionally simple so physics, animation selection, and trace behavior can be isolated from retail stage geometry, SET objects, cameras, and scripting.

**Project law remains:** 1 P, no Rs — PORT. No remake. No remaster. Just a port with QoL.

## New White Zone course
A separate `parity_lab` world was added rather than modifying the frozen Movement Lab fixture. It contains nine adjacent sections:

1. CALIBRATION
2. ACCELERATION
3. BRAKE / COAST
4. JUMP
5. ROLL / SPINDASH
6. SLOPE UP
7. PLATEAU
8. SLOPE DOWN
9. AIR / LANDING

The course is 24 world units wide and has 10-unit measurement markers. Slope-up rises 8 units over 40 units; slope-down mirrors it. These dimensions are test-fixture choices, not claims about any retail stage.

## Physics-synced real Sonic
The existing read-only animation intent observer is now paired with a runtime dense-animation resolver. The following dense-ID -> CHRMODELS ACTION relationships are source-backed and encoded directly: Stand 0->1, Walk1 9->3, Walk2 10->4, Walk3 11->5, Run1 12->6, Run2 13->18, Jump/Spin 14->14, Roll 15->14, Spring 16->8, Spring->Fall 17->9, Fall 18->10, Land 19->11, Brake 20->7, Uncurl 29->22, Turn Around 30->20, Skidding 31->19, Spin Ball 32->21.

The *selection policy* that chooses among those IDs from broad physics intents is deliberately marked PROVISIONAL. `jog_speed` and `run_speed` remain evidence-backed speed-class parameters, not proven retail animation-switch thresholds. 0E's 0.5 source-frame/tick playback is also retained only as a hardware-test baseline, not claimed as retail playback rate.

The 3DS runtime includes a byte-compare guard around the completed `SA1PlayerState` before/after animation observation + selection. Any animation write-back into physics is treated as a runtime failure.

## 1:1 check protocol
`tools/run_white_zone_protocol.c` generates deterministic CSV v6 traces for:

- flat acceleration
- coast from controlled speed
- brake/reverse from controlled speed
- jump tap
- jump hold
- Spin Dash charge/release
- uphill
- downhill

Each scenario is currently deterministic on SA3DS. This is NOT yet a retail 1:1 result. A scenario becomes `VERIFIED_1TO1` only after a reproducible retail-reference trace or equivalent direct evidence is compared under documented tolerances.
