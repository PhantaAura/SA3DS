# 0.0.9.0D Real Sonic White-Space Render Gate

## Pipeline

`CHRMODELS_orig.dll -> semantic decode -> SA3C -> native pose/world matrices -> draw submission`

`SONIC.PVM -> PVRT decode -> SA3T -> texture lookup`

The host raster smoke combines both streams and validates that a real animated Sonic pose can be traversed, transformed, triangulated, textured, depth-tested, and rasterized without any Sega-derived payload being committed to the checkpoint.

## Source semantics locked in this gate

### Ninja object flags
- UNIT_POS: ignore translation
- UNIT_ANG: ignore rotation
- UNIT_SCL: ignore scale
- HIDE: do not draw model
- BREAK: terminate child traversal
- ZXY/ZYX rotation flag is preserved
- SKIP/NoAnimate is kept distinct from display hiding

### Transform order
SA Tools' SADX model path applies translation, then either XYZ or ZYX Ninja rotation semantics depending on object flags, then scale. The runtime pose path mirrors those semantics rather than using a generic skeleton convention.

### Basic UV
For little-endian Basic models, SA Tools decodes U and V from signed 16-bit values divided by 255 for normal UV precision. 0D locks that source conversion for this PC2004 Sonic profile.

### Basic polygon triangulation
- Triangle: unchanged
- Quad: `(0,1,2)` + `(2,1,3)`
- Strip: alternating winding matching SA Tools' `Strip.Reversed` semantics

### Motion interpolation
The Ninja motion header stores interpolation-function bits in mask `0x00C0`:
- `0x0000` linear
- `0x0040` spline
- `0x0080` user

All 146 populated Sonic motions in the exact supported character DLL have the interpolation-function bits clear, so this gate uses source-supported linear key sampling.

## Runtime animation remap
The 2004 executable builds a dense 146-entry `SonicAnimData` table. It does **not** correspond 1:1 to the 149 exported `___SONIC_ACTIONS` indices. The reconstruction report in `PC2004_SONIC_ANIMDATA_REMAP.json` provides the complete dense-ID -> exported-action-slot mapping. Dense IDs 75 and 76 are null by construction.

Core movement examples:
- Stand dense 0 -> source action 1
- Walk1 dense 9 -> source action 3
- Walk2 dense 10 -> source action 4
- Walk3 dense 11 -> source action 5
- Run1 dense 12 -> source action 6
- Run2 dense 13 -> source action 18
- JumpOrSpin dense 14 -> source action 14
- Roll dense 15 -> source action 14
- Spring dense 16 -> source action 8
- Fall dense 18 -> source action 10
- Land dense 19 -> source action 11
- Brake dense 20 -> source action 7
