## Proven source layouts promoted in this gate

### Object — 0x34 bytes

- `+0x00` flags
- `+0x04` model pointer
- `+0x08` translation XYZ (`float32`)
- `+0x14` rotation XYZ (`int32` source angles)
- `+0x20` scale XYZ (`float32`)
- `+0x2C` child pointer
- `+0x30` sibling pointer

`+0x04`, `+0x2C` and `+0x30` were already independently proven by the exact
Mod Loader walker. The complete record is now structurally validated across the
real Sonic hierarchy.

### Action — 8 bytes

- `+0x00` object/root pointer
- `+0x04` motion pointer

### Motion header — 12 bytes

- `+0x00` per-node motion-data pointer
- `+0x04` frame-domain/count field
- `+0x08` packed type/interpolation halves

All 146 populated Sonic actions validate.

Observed exact distributions:

- type 3 / interpolation 2: 136 motions
- type 7 / interpolation 3: 10 motions
- 126 motions have 73 nodes
- 1 motion has 74 nodes
- 19 motions have 1 node
- frame domains range from 7 through 100

Type 3 uses a 16-byte per-node record containing position/angle pointers and
counts. Type 7 uses a 24-byte per-node record adding scale pointer/count.

Key records are 16 bytes:

- position/scale: `u32 frame + float32 XYZ`
- rotation: `u32 frame + int32 XYZ source angles`

Across all populated actions the exact decoder validates:

- 468 position channels / 5,570 position keys
- 3,392 rotation channels / 80,286 rotation keys
- 23 scale channels / 348 scale keys

## Model data

The exact Sonic model record is structurally self-consistent at 0x2C bytes:

- points pointer
- normals pointer
- point count
- meshset pointer
- material pointer
- meshset/material counts
- center XYZ
- radius
- original texture ID

For Sonic's model data this gate also proves:

- 0x1C-byte meshset records;
- 0x14-byte material records;
- signed-16 UV pairs;
- `0xC000` primitive class as strip lists;
- `0x4000` primitive class as quad lists;
- all decoded point/normal arrays are finite;
- all geometry indices stay within their model point counts.

Unused meshset pointer-slot historical names are deliberately not guessed.

## Exact SONIC.PVM

The exact matching archive parses as:

- `PVMH`
- flags `0x000F`
- 16 texture entries
- 16 matching `PVRT` chunks
- local texture indices 0..15
- global indices 1000..1015
- pixel formats 0, 1 and 2
- data format 9 for all entries
- sizes 8x8, 16x16, 32x32, 64x64 and 128x128

All 16 largest mip levels decode to RGBA8 in the importer. No decoded texture
payload is included in the checkpoint.

Character materials across all action hierarchies reference 13/16 local Sonic
texture slots, all in range.
