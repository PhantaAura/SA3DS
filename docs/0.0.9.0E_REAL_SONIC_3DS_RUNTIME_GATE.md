# 0.0.9.0E Real Sonic 3DS Runtime Gate

## Purpose

0.0.9.0E is the first SA3DS checkpoint whose source is structured to put the decoded PC2004 Sonic character directly through **libctru + Citro3D + PICA200** on Nintendo 3DS hardware.

The gate deliberately separates two claims:

1. **Source/build readiness** — verified in this checkpoint.
2. **Physical Old 3DS execution** — must be verified on the user's devkitARM installation and hardware.

## Runtime pipeline

```text
user-owned CHRMODELS.DLL + SONIC.PVM
              ↓
exact hash verification
              ↓
SA3C character package + SA3T texture package
              ↓
RomFS
              ↓
3DS SA3C/SA3T readers
              ↓
real ACTION/MOTION pose sampler
              ↓
Ninja hierarchy/world transforms
              ↓
CPU-expanded dynamic draw vertices (0E correctness path)
              ↓
Citro3D / PICA200
              ↓
textured real Sonic on top screen
```

## Why 0E CPU-expands triangle vertices

The 0E hardware gate optimizes for correctness and observability, not final draw efficiency. A normal Sonic pose contains only 1,993 source triangles, so expanding each draw to a small linear-memory vertex stream is acceptable for the initial proof and removes indexed-buffer remapping as a second simultaneous variable.

After hardware profiling, 0F/0G may move to persistent indexed VBOs, draw sorting and tighter texture state changes if the measurements justify it.

## Character data handled

Normal Sonic hierarchy:

- 73 reachable nodes
- 28 visible model nodes in normal pose
- 42 mesh submissions
- 1,993 source triangles

ACTION 14 alternate Jump/Roll hierarchy:

- separate validated root
- 41 mesh submissions
- 1,001 source triangles

The runtime chooses the root carried by the selected real ACTION slot; it does not force every animation onto the normal 73-node root.

## Citro3D choices

The source uses the same core API family as public devkitPro Citro3D examples:

- `C3D_Init`
- `C3D_RenderTargetCreate`
- `C3D_RenderTargetSetOutput`
- `DVLB_ParseFile` / `shaderProgramSetVsh`
- `AttrInfo_AddLoader`
- `BufInfo_Add`
- `Mtx_PerspTilt`
- `C3D_FVUnifMtx4x4`
- `C3D_DepthTest`
- `C3D_AlphaTest`
- `C3D_TexBind`
- `C3D_DrawArrays`

The texture upload path explicitly converts conventional row-major RGBA8 into PICA200 tiled texture memory using a display transfer. This is intentional: Citro3D's basic texture image copy does not perform that tiling transformation for arbitrary owner-source pixels.

## Physics boundary

No frozen physics source is modified by 0E. The renderer consumes character presentation state only. The existing physics→animation one-way contract remains in force.

Physics-driven semantic selection is intentionally left for 0.0.9.0F after real hardware render correctness is proven.
