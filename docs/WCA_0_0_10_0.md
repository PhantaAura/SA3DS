## CP1 — native input, camera and display-frame correction

Reproduced defects:

1. At camera yaw45 degrees, old White Zone projection sends camera-forward to
   screen-X1 instead of0. Its world rotation signs disagree with the chase view.
2. RH Emerald Coast `LookAt(false)` screen-right is
   `(-cos(cameraYaw),0,sin(cameraYaw))`. Positive native stick X previously
   requested the opposite tangent.
3. The old EC adapter assumed model+X forward. Exact movement code
   `0x43ECE3..0x43ECFA` rotates by `-taskY`; Sonic display
   `0x494A41..0x494A5E` rotates by `0x8000-taskY`, using the same Ninja helper.
   This proves a half-turn about local Up: model **-X** follows physical forward.
   White Zone previously omitted its model-axis conversion altogether.

Implementation: `player_view` converts native screen input once before physics,
retaining raw provenance and all button fields. White Zone points now use the
RH camera basis; its model angle is `playerYaw-cameraYaw-PI/2`. EC retains its
unit support frame and center_height5.4 anchor, with forward/right model columns
rotated180 degrees. Physical heading still comes from the existing controller;
turn inertia, PC2004 filtering,156 scale and60Hz simulation are unchanged.
Host owner replay now applies the same screen/core conversion as native replay.

Original evidence: private decompilation, exact executable signature verifier,
and Citro3D's [RH LookAt](https://github.com/devkitPro/citro3d/blob/master/source/maths/mtx_lookat.c)
and [RotateY](https://github.com/devkitPro/citro3d/blob/master/source/maths/mtx_rotatey.c)
